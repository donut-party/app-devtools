# donut app-devtools

Developer tools:

- system explorer
- db info

## dev

Start the app in the `example` directory (`npm install && npm run dev`) to
see it at work, then view http://localhost:3000/donut/app-devtools

## using app-devtools

In an app generated by `donut new`, run the install generator:

``` shell
donut generate --lib party.donut/app-devtools:<version> :donut.app-devtools.generators/install
```

It:

- adds `party.donut/app-devtools` to `deps.edn`
- adds an `:app-devtools` build to `shadow-cljs.edn` (its output dir goes
  into the `:dev-http` roots)
- declares that build as a script in `deps.edn`'s `:donut/scripts` and adds
  it to `:default`, so `npm run dev` watches it next to `:dev`:

  ``` clojure
  :donut/scripts
  {:default ["dev" "tailwind:watch" "app-devtools"]
   :scripts {"app-devtools" {:shadow-build :app-devtools}
             ...}}
  ```

- adds `donut.app-devtools.backend.plugin/app-devtools-plugin` to the
  backend system's `::ds/plugins`, which mounts app-devtools' endpoints

`donut.app-devtools.frontend.core` gets the backend routes (the app's and
app-devtools' own) from `donut.bakery.inject/backend-routes`, so the app
must run on [bakery](https://github.com/donut-party/bakery) the way the
template sets it up: `donut.bakery.registry/RouteRegistryComponent` in the
backend system, and `npm run dev` (`clojure -M:dev:cljs:bakery`) running the
backend and shadow-cljs in one JVM. Every build that compiles a namespace
using the inject macro lists `donut.bakery.inject` in its `:cache-blockers`;
the generated `:app-devtools` build does.
